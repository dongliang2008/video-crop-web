## 0. 项目概述

**目标**：构建一套**完全本地、离线运行**的视频裁剪 Web 平台：用户打开任意视频 → 框选 1 个画面裁剪区域 → 设 N 个时间段（帧级起止）→ **每个时间段独立选择**竖屏 1080×1920 / 横屏 1920×1080 / 两者都要 → 每个时间段独立产出 MP4 → 水印处理（多区域）→ 出片前确认图 → 出片后 AI 三帧识别 + 源文件名关键词综合命名。

**核心约束**：
- 不依赖网络（仅 AI 识别调用智谱 API，其余全本地；按需启用）
- 复用已确认规则：《竖屏_横屏_水印处理说明.md》（画幅标准/水印环带填充/坐标映射/状态机/命名）+《项目说明.md》（AI 打标命名规则）
- 技术栈：Python 3.10（D:\Python310）+ Flask + SQLite + ffmpeg 9.0.1（已在 PATH）+ 原生 HTML/CSS/JS（无构建）

**形态**：本地网页应用（浏览器打开 localhost 页面 + Python 本地服务）。

## 2. 核心处理链设计

### 2.1 总体链路

```
打开源视频 → ffprobe 探测(分辨率/时长/帧率)
  → ① 画面框选：抽帧作底图，Canvas 拖拽 1 个矩形 → 记录 crop(x,y,w,h)【源像素坐标】
  → ② 水印框选（可选，多区域）：同样基于源画面 → 记录 wm(x,y,w,h,σ)【源像素坐标】
  → ③ 时间拆段：播放器帧级步进，选起始帧/结束帧 → 记录 start/end【浮点秒】
  → ④ 任务生成：**每个时间段独立选择 竖屏/横屏/两者都要** → 每段按其方向生成 1~2 条任务
  → ⑤ 启动任务：先渲染 1 帧完整滤镜链预览图 → WAIT_CONFIRM「待确认」
  → ⑥ 用户确认 → 单条 ffmpeg 编码出片 → DONE
  → ⑦ AI 命名：出片后弹窗选 3 帧 → 逐帧识别(带源文件名上下文) → 综合命名 → 重命名
```

### 2.2 滤镜顺序（单条 filter_complex，一次解码一次编码）

处理项顺序固定：**画面裁剪(crop) → 竖屏/横屏标准化 → 水印填充 → (可选增强) → 输出**

```
ffmpeg -ss <start> -i 源视频 -t <dur> -filter_complex "..." -map [out] -map 0:a? -c:v libx264 -c:a aac 输出.mp4
```

竖屏 + 去水印示例（框选区域 cw×ch at (cx,cy)，水印坐标经映射为映射后值）：

```
[0:v]crop=cw:ch:cx:cy,split=2[bg][main];
[bg]scale=270:480:force_original_aspect_ratio=increase,crop=270:480,gblur=sigma=40,scale=1080:1920[bg2];
[main]scale=1080:-2[main2];
[bg2][main2]overlay=(W-w)/2:(H-h)/2[vrt];
[vrt]null[wm0]; [wm0]split=2[wm1a][wmc0];
[wmc0]crop=区域宽:区域高:映射x:映射y,geq=r='...':g='...':b='...',crop=区域宽:区域高:0:0[wm1b];
[wm1a][wm1b]overlay=映射x:映射y[wm1];
[wm1]null[wmout]
```

横屏示例：`[0:v]crop=cw:ch:cx:cy,split=2[bg][main]; [bg]scale=480:270:force_original_aspect_ratio=increase,crop=480:270,gblur=sigma=40,scale=1920:1080[bg2]; [main]scale=-2:1080[main2]; [bg2][main2]overlay=(W-w)/2:(H-h)/2[hrt]; ...`

### 2.3 坐标映射（关键）

用户所有框选（裁剪区、水印区）均基于**源画面任意一帧**，坐标是源像素；经过 crop 和标准化后画幅改变，必须逐层换算：

```
源坐标 → ① crop 后坐标 → ② 竖/横屏标准画幅坐标
```

**① crop 后**（相对裁剪区域）：
- 裁剪区：`(cx, cy, cw, ch)`
- 水印区源坐标 `(wx, wy, ww, wh)` → 相对坐标 `(rx, ry) = (wx-cx, wy-cy)`
- 完全落入 crop 外（`rx+ww<=0 或 rx>=cw 或 ry+wh<=0 或 ry>=ch`）→ **剔除**（画面被裁掉，不可见）
- 部分越界 → 向内 clamp

**② 标准化**：
- 竖屏：主画面 `scale=1080:-2`，缩放因子 `k = 1080/cw`，主画面高 `main_h = ch*k`（取偶），垂直居中偏移 `offset_y = (1920-main_h)//2`；映射 `(rx*k, ry*k+offset_y)`
- 横屏：主画面 `scale=-2:1080`，`k = 1080/ch`，主画面宽 `main_w = cw*k`，水平居中偏移 `offset_x = (1920-main_w)//2`（宽不足为正、超宽为负）；映射 `(rx*k+offset_x, ry*k)`；超宽裁切区内的水印剔除、越界 clamp

> 与《竖屏_横屏_水印处理说明.md》第 5 节同机制，仅中间多一层 crop 换算。

### 2.4 确认图与任务状态机

沿用既有规则（**生成视频前必须先出确认图**）：
- 任务启动 → 先 `-frames:v 1` 渲染完整滤镜链预览 PNG → `WAIT_CONFIRM`（待确认）
- 界面弹「查看/确认输出」→ 用户确认 → 编码最终视频 → `DONE`
- 状态：`PENDING → RUNNING → WAIT_CONFIRM → DONE / FAILED / CANCELED`

### 2.5 时间段 → 任务模型（每段独立选方向）

```
项目 project：1 个源视频 + 1 个裁剪区 + N 个水印区
  └─ 时间段 segment：N 个（各含 start/end，帧级 + 各自的方向选择）
      │   段1（5~20s）：竖屏     → 任务1：<源名>_段1_竖屏.mp4
      │   段2（20~30s）：横屏    → 任务2：<源名>_段2_横屏.mp4
      │   段3（40~50s）：两者都要 → 任务3：<源名>_段3_竖屏.mp4 + 任务4：<源名>_段3_横屏.mp4
      └─ 每段方向独立：vertical / horizontal / both，互不影响
```

- **方向是段级属性**：每段各自选择竖屏/横屏/两者都要，不是全局勾选
- 每段任务独立出片、独立命名、互不影响
- 源已是标准画幅且未框选 → 跳过 crop，仅做标准化（等同原样）/水印

## 3. SQLite 表结构

```sql
-- 项目表（1 源视频 + 裁剪区 + 水印区 + 方向选项）
CREATE TABLE projects (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,              -- 项目名（默认=源文件名）
    src_path TEXT NOT NULL,          -- 源视频绝对路径
    src_w INTEGER, src_h INTEGER,    -- 源分辨率（ffprobe）
    src_duration REAL, src_fps REAL, -- 源时长/帧率
    crop_x INTEGER, crop_y INTEGER,  -- 裁剪区域（NULL=不裁剪）
    crop_w INTEGER, crop_h INTEGER,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 水印区域表（多区域）
CREATE TABLE watermark_regions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL,
    x INTEGER, y INTEGER, width INTEGER, height INTEGER,
    blur_sigma REAL DEFAULT 30,
    FOREIGN KEY (project_id) REFERENCES projects(id)
);

-- 时间段表（帧级起止 + 各自方向）
CREATE TABLE segments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL,
    seg_index INTEGER NOT NULL,      -- 段序号
    frame_start INTEGER,             -- 起始帧号（可选）
    frame_end INTEGER,               -- 结束帧号（可选）
    start_time REAL NOT NULL,        -- 起始秒（浮点，精确到帧）
    end_time REAL NOT NULL,          -- 结束秒
    direction TEXT DEFAULT 'both',   -- 本段方向：'vertical' | 'horizontal' | 'both'（段级独立选择）
    FOREIGN KEY (project_id) REFERENCES projects(id)
);

-- 任务表（每段 × 方向）
CREATE TABLE tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id INTEGER NOT NULL,
    segment_id INTEGER NOT NULL,
    direction TEXT NOT NULL,         -- 'vertical' | 'horizontal'
    state TEXT DEFAULT 'PENDING',   -- PENDING/RUNNING/WAIT_CONFIRM/DONE/FAILED/CANCELED
    progress REAL DEFAULT 0,
    preview_path TEXT,               -- 确认图路径
    preview_approved INTEGER DEFAULT 0,
    output_path TEXT,                -- 最终输出路径
    error TEXT DEFAULT '',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (project_id) REFERENCES projects(id),
    FOREIGN KEY (segment_id) REFERENCES segments(id)
);
```

| `POST /api/tasks/<tid>/cancel` | 取消任务 |
| `POST /api/ai/recognize` | 单帧 base64 → 智谱识别（带源文件名上下文） |
| `POST /api/ai/rename` | 综合源文件名词 + 帧识别词 → 规范文件名 |
| `POST /api/rename` | 重命名产出文件（后缀不变、重名 _01） |
| `GET /api/config` | 读取命名配置（国家名单等） |

## 5. 前端交互设计要点

1. **帧级选时**：播放器 + 步进按钮（±1 帧 = 1/fps 秒、±1s、±5s），显示当前帧时间；「设起始帧/设结束帧」写入时间段。
2. **裁剪框选**：抽当前帧为底图 → Canvas 拖拽画 1 个矩形（自由比例），实时显示 x/y/w/h 与框内尺寸；可重新框选。
3. **水印框选**：同画布切换模式，可画多个矩形（复用 video-clipper watermark_dialog 交互：选中/微调/删除/σ 调节）。
4. **时间段列表**：每段显示 起止帧时间/时长 + **方向选择（竖屏/横屏/两者都要，段级独立）**；可增删改；任务按段展示方向、状态、确认图。
5. **确认图弹窗**：启动任务后弹出预览图，「确认输出/取消」。
6. **AI 命名弹窗**：出片后点「AI 命名」→ 播放产出视频 → 截取帧1/2/3 → 逐帧识别 → 「确定：综合命名」→ 回填重命名框。

## 6. AI 命名模块设计

**输入**：产出视频 3 帧（base64 data URL）+ **源文件名关键词**（作为上下文随请求一起发送）
**识别**：智谱 GLM-4V（`glm-4v-flash` → `glm-4.6v-flash` 回退；timeout 120s；max_tokens 512；temperature 0.1；请求间隔 1s；key 复用 video-manager `config.json` 的 `vision_api`）
**提示词要点**：告知 AI "该视频由 <源文件名> 裁剪而来，源文件关键词为：<解析词>；请结合源文件名关键词与 3 帧画面内容，综合输出 3~6 个最能代表视频内容的关键词，合并去重、相近词合并，不要输出时间/日期/纯数字/模板词（通用、XX、横屏、竖屏、段、裁剪、去水印）"
**组装**：`{首词}_{词1}_{词2}_..._{横屏|竖屏}`
- 首词优先级：路径含国家文件夹名 > AI 综合词中的国家 > 通用
- 方向：任务方向已知（竖屏/横屏）直接沿用
- 80 字符截断兜底；重名自动 `_01`
- 源文件名解析失败或识别为空 → 沿用任务默认名

## 7. 性能与约束

- 单条 ffmpeg 命令完成全部处理（一次解码一次编码），性能与 video-clipper V1.4 一致
- 画幅偶数要求：所有宽高经 `_even()` 处理（yuv420p）
- `geq` 表达式单引号包裹（避免 mod() 内逗号被解析分割）
- 确认图可覆盖重生成；任务并发默认 2（沿用安全并发结论）
- 输出/预览默认到项目 `output/`；按素材加工备份规则，产物可复制回源目录加标记后缀
